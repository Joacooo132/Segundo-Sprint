Densidad de defectos

Objetivo < 2.0

1.2 def/kloc

Cantidad de bugs confirmados por cada mil líneas de código fuente en producción.

Cobertura de pruebas

Saludable

84 %

Porcentaje de código ejecutado durante las pruebas unitarias y de integración automáticas.

Tiempo medio de resolución

Críticos

3.5 horas

Excelente

720 horas

Tiempo medio entre fallos consecutivos del sistema bajo cargas nominales normales de producción.

Estándares ISO de calidad

Modelo de Calidad del Producto: ISO 9126

Estándar internacional que clasifica la calidad del producto software en 6 características clave esenciales para la confiabilidad.

Funcionalidad

Grado en que el software provee funciones que cumplen con las necesidades declaradas.

Fiabilidad

Capacidad del producto para mantener un nivel especificado de rendimiento bajo condiciones dadas.

Usabilidad

Atributos del software que facilitan que sea comprendido, aprendido, usado y atractivo al usuario.

Eficiencia

Nivel de desempeño en relación con la cantidad de recursos de cómputo utilizados.

Mantenibilidad

Facilidad y esfuerzo necesario para realizar modificaciones, adaptaciones o correcciones técnicas.

Portabilidad

Capacidad de la aplicación informática para transferirse de un entorno o plataforma a otro.

Familia SQuaRE: ISO/IEC 25000

Evolución de ISO 9126. Su modelo de calidad del producto (ISO/IEC 25010) amplía la evaluación a 8 características.

Adecuación funcional

Las funciones cubren las necesidades declaradas e implícitas de forma completa y correcta.

Eficiencia de desempeño

Tiempos de respuesta y uso de recursos adecuados bajo las condiciones establecidas.

Compatibilidad

Capacidad de intercambiar información y convivir con otros sistemas en el mismo entorno.

Usabilidad

Facilidad para aprender, operar y usar el producto, con una interfaz accesible y agradable.

Fiabilidad

Funciona sin fallos durante un período determinado y se recupera ante errores.

Seguridad

Protege la información y los datos, con acceso solo para personas y sistemas autorizados.

Mantenibilidad

El producto puede modificarse, corregirse y probarse con eficacia y eficiencia.

Portabilidad

Se adapta, instala o reemplaza en distintos entornos de hardware o software.

DE LO PEQUEÑO AL SISTEMA

Tres niveles, una cobertura coherente

Cada nivel responde una pregunta distinta y reduce riesgos antes de llegar a producción.

01

Unitarias

Alcance: Una función o clase · Velocidad: Muy rápidas

Aíslan errores en la base del código.

02

Integración

Alcance: Módulos conectados · Velocidad: Rápidas

Comprueban contratos, APIs y datos.

03

Sistema

Alcance: Producto completo · Velocidad: Más lentas

Validan recorridos reales de principio a fin.

Combina la mirada del comportamiento observable con el conocimiento de la estructura interna.

Caja Negra

¿Qué hace el software?

Se diseña desde: Requisitos, entradas y salidas

Ideal para validación funcional y aceptación.

Caja Blanca

¿Cómo lo hace?

Se diseña desde: Código, decisiones y caminos

Ideal para localizar huecos lógicos y medir cobertura.

TARJETAS DESPLEGABLES

Técnicas para diseñar mejores casos

Estados abiertos y cerrados muestran cómo profundizar sin perder una lectura escaneable.

CAJA NEGRA

Partición de equivalencia

Agrupa entradas con comportamiento equivalente y prueba un valor representativo de cada grupo.

Ejemplo: para una edad válida de 18–65, probar 25 representa la partición válida.

CAJA NEGRA

Valores límite

Prioriza los bordes de cada rango, donde suelen concentrarse los defectos.

Ejemplo: para el rango 18–65, probar 17, 18, 65 y 66.

CAJA BLANCA

Cobertura de sentencias y ramas

Mide qué instrucciones y decisiones internas fueron ejecutadas por el conjunto de pruebas.

Objetivo práctico: cubrir cada rama relevante sin perseguir un 100% vacío de intención.

CAJA BLANCA

Pruebas de caminos

Diseña casos para recorrer secuencias lógicas independientes del código.

Ejemplo: una función con dos decisiones tiene tres caminos independientes que conviene probar.
